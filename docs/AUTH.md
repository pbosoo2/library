# Vercel 비밀번호 인증

## 환경변수
Vercel 프로젝트의 Settings → Environment Variables에 아래 값을 Sensitive로 등록하고 Production과 사용할 Preview 환경에 적용합니다. 값은 채팅이나 저장소에 넣지 않습니다.
- LIBRARY_PASSWORD: 8자 이상의 비밀번호. 가능하면 12자 이상의 강한 비밀번호를 권장합니다.
- SESSION_SECRET: 32자 이상의 무작위 시크릿. 비밀번호 관리자로 64자 이상 무작위 값을 생성하는 것을 권장합니다.
- NOTION_TOKEN: 기존 값을 유지합니다.
변경 후 Redeploy가 필요합니다. 필수 인증 변수가 없거나 짧으면 데이터 접근은 차단됩니다.

## 세션
쿠키는 Secure, HttpOnly, SameSite=None, Partitioned, Path=/인 __Host- 쿠키입니다. Expires/Max-Age를 넣지 않아 브라우저 세션 동안 유지됩니다. 보안을 위해 서버에서 세션 발급 후 최대 7일로 제한합니다. 비밀번호 또는 세션 시크릿을 바꾸면 기존 세션은 무효화됩니다.
웹사이트는 컴퓨터 전원 종료를 신뢰성 있게 감지할 수 없습니다. 브라우저 세션 복원 기능이 쿠키를 복원할 수 있으므로 종료 시 로그아웃 보장은 하지 않습니다. 확실하게 종료하려면 타이머 패널의 로그아웃 버튼을 사용합니다. 로그아웃은 해당 브라우저의 쿠키를 삭제하며 이미 복사된 토큰을 서버에서 개별 폐기하지는 않습니다.

## 보호 범위와 남은 공개 경로
Vercel의 페이지, API, data 파일과 표지 파일은 서버 미들웨어로 보호됩니다. 인증된 응답은 CDN/브라우저 공유 캐시를 사용하지 않습니다. API 자체에도 인증 검사가 있습니다. 로그인 시도 제한은 서버 인스턴스 내 보조 제한이며 분산 환경의 완전한 차단 장치는 아닙니다.
GitHub Pages에는 이 서버 인증이 적용되지 않습니다. 화면은 Vercel로 이동하지만 공개 저장소와 Pages의 기존 데이터 파일, git 이력까지 비공개가 되는 것은 아닙니다. 완전한 비공개를 원하면 GitHub Pages 공개를 중단하고 저장소를 Private으로 변경해야 합니다. 이전 배포 주소/기존 공개 복사본도 별도로 확인해야 합니다. 이미 공개된 데이터의 회수는 보장할 수 없습니다.

## 유지되는 동작
처음 열기/새로고침, 1시간 자동 조회, 바로 동기화 버튼을 통한 조회는 로그인한 상태에서 작동합니다. 다른 탭에서 돌아왔을 때는 데이터를 조회하지 않습니다.

## 노션 임베드
노션 페이지에서 /embed를 선택하고 https://library-rose-alpha.vercel.app/ 주소를 넣습니다. 프레임은 Notion 및 Notion이 사용하는 Iframely 도메인만 허용합니다. 비밀번호 검증과 API 인증은 그대로 유지됩니다.
Partitioned 세션 쿠키를 사용하므로 임베드 안에서는 처음 한 번 별도로 로그인해야 할 수 있습니다. 일반 탭과 임베드의 세션은 자동 공유되지 않습니다. 브라우저/Notion 앱의 쿠키 제한이나 임베드 정책에 따라 로그인 유지가 되지 않을 수 있으며, 이때는 로그인 화면의 새 탭에서 열기를 사용합니다. 세션 쿠키이므로 컴퓨터 종료 시 로그아웃을 보장하지 않습니다.
