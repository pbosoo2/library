# 도서관 변경분 동기화

## 환경변수

Vercel Upstash 연결에서 자동 등록된 쓰기 권한 변수:

- `KV_REST_API_URL`
- `KV_REST_API_TOKEN`

직접 연결한 경우 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`도 지원합니다.
`KV_REST_API_READ_ONLY_TOKEN`, `KV_URL`, `REDIS_URL`은 이 구현에서 사용하지 않습니다.
비밀 값은 브라우저, 저장소, API 응답으로 보내지 않습니다. 환경변수는 배포에 적용되어야 합니다.

## 조회 흐름

- 화면 최초 로드, 기존 1시간 자동 조회, ‘동기화’ 버튼에서만 조회합니다.
- 탭으로 돌아오거나 페이지 넘김·검색·필터·소개 펼치기를 할 때는 서버를 조회하지 않습니다.
- Redis에 저장된 목록이 없으면 두 노션 데이터 소스를 모두 읽어 초기 목록을 만듭니다.
- 이후에는 이전 조회 시작 시각보다 2분 앞선 시점부터 `last_edited_time`으로 필터링하여 변경분을 읽습니다. 시간 경계/인덱스 지연 누락을 줄이기 위해 직전 변경분 일부가 중복 조회될 수 있습니다.
- 노션 페이지 ID별로 저장된 읽기 전용 표시 필드를 병합한 뒤 제목별 회차, 상태, 전체 통계를 다시 계산합니다. 이름이 바뀌거나 비워진 항목도 처리합니다.
- 목표 데이터도 같은 방식으로 변경분을 병합합니다.
- Redis에는 화면에 필요한 필드만 저장하며 노션 페이지 본문/비공개 메모/자격증명은 저장하지 않습니다.
- 실패한 조회에서는 저장된 데이터나 마지막 성공 시각을 덮어쓰지 않습니다. 브라우저는 기존 화면을 유지합니다.
- 여러 요청이 겹치면 인스턴스 내부 Promise와 Redis 잠금으로 중복 작업을 줄입니다. 잠금을 잃은 요청은 최신 데이터를 덮어쓰지 않습니다.

## 전체 대조와 이미지 예외

수정 시각 쿼리만으로는 삭제·휴지통 이동·다른 데이터 소스로 이동한 항목을 모두 찾을 수 없습니다.
마지막 전체 대조로부터 24시간이 지난 후 들어오는 첫 조회는 전체 데이터를 다시 읽어 삭제/이동 항목을 제거합니다.
따라서 삭제/이동은 일반 변경분 조회에서 즉시 반영되지 않을 수 있습니다.
별도 cron, 웹훅, GitHub Actions 자동 실행은 추가하지 않습니다.

노션에 업로드한 표지 파일의 서명 URL이 만료될 예정이면, 변경되지 않은 도서라도 해당 페이지를 추가 조회하여 표지 링크를 갱신합니다.
외부 표지 URL은 이 추가 조회를 하지 않습니다. Redis 캐시 소실, 버전 변경, 노션 토큰 변경 시에도 전체 초기 조회가 필요합니다.

브라우저에는 병합된 전체 목록을 전달합니다. ‘변경분만 조회’는 노션에서 가져오는 데이터 범위를 뜻하며 브라우저 전송까지 델타 방식이라는 의미는 아닙니다.

## 수동 전체 동기화와 갱신 정보

‘전체 동기화’ 버튼은 `GET /api/library?full=1`을 호출하여 24시간 경과 여부와 무관하게 두 데이터 소스의 전체 목록을 다시 대조합니다.
인증과 읽기 전용 보호는 유지합니다. 성공하면 마지막 전체 대조 시각도 갱신하며 실패하면 이전 데이터를 보존합니다.
일반 동기화와 전체 동기화가 겹쳐도 전체 요청을 변경분 결과로 대체하지 않습니다.

API config의 `updatedAt`은 마지막 성공 조회 완료 시각, `fullUpdatedAt`은 마지막 성공 전체 대조 완료 시각입니다.
화면 맨 아래 ‘최근 갱신 정보’는 기본 닫힘 상태이며 한국 시간 기준 최근 갱신 시각, 최근 목록 대조 날짜, 다음 갱신까지 남은 시간, 자동 갱신 간격과 상태를 표시합니다.
펼침/닫힘과 초 단위 남은 시간 표시는 API 조회를 하지 않습니다.

## 화면

도서를 한 페이지에 4권씩 보여줍니다. 이전·다음 버튼은 저장된 목록 안에서 이동하며 추가 API 요청을 하지 않습니다.
검색·상태 필터를 바꾸면 1페이지로 돌아갑니다. 동기화 후에는 현재 페이지를 유지하고, 페이지 수가 줄면 마지막 유효 페이지로 조정합니다.
통계는 현재 페이지의 4권이 아니라 전체 목록으로 계산합니다. 모바일에서는 기존 반응형 열 배치를 유지합니다.

## 검증

`npm test`로 인증, Redis REST 명령, 전체 초기 조회, 빈 변경분, 수정/추가/이름 변경, 목표, 페이지네이션, 실패 시 시각 보존, 삭제 대조, 만료 표지 갱신, 잠금 충돌을 테스트합니다.
실제 배포 확인 시 최초 조회 후 도서 하나를 수정하고 ‘동기화’를 눌러 결과를 확인합니다.
